## 2. Основная часть

### 2.1 Архитектура системы
Система спроектирована с использованием микросервисного подхода. Основные компоненты:
1.  **Shipments Service**: Сервис на базе gRPC, отвечающий за бизнес-логику и хранение данных.
2.  **API Gateway**: Прокси-сервис на базе FastAPI, преобразующий внешние REST-запросы в gRPC-вызовы.

Схема взаимодействия:
`Client -> [REST] -> Gateway -> [gRPC] -> Shipments Service`

### 2.2 Реализация gRPC интерфейса
Определение сервиса в файле `shipments.proto`:

```proto
service ShipmentsService {
  rpc GetShipment (GetShipmentRequest) returns (GetShipmentResponse);
  rpc CreateShipment (CreateShipmentRequest) returns (CreateShipmentResponse);
  rpc ListShipments (ListShipmentsRequest) returns (stream Shipment);
}
```

### 2.3 Реализация API Gateway
Gateway реализует эндпоинты:
- `GET /api/shipments` — получение списка всех доставок.
- `POST /api/shipments` — создание новой доставки.
- `GET /api/shipments/{id}` — получение информации о конкретной доставке.
