# Вопросы для самопроверки

1. Какие критерии вы использовали при разделении монолита на микросервисы (или при проектировании сервисов)?
Разделение проводилось по принципу ответственности (Single Responsibility) и бизнес-функциям. Сервис счетов (invoices) выделен в отдельный домен для независимого масштабирования.

2. Почему вы выбрали именно этот стек технологий (язык, БД, протоколы)?
Python выбран за скорость разработки, а gRPC — для эффективного и строго типизированного взаимодействия между внутренними сервисами. REST используется для внешней доступности.

3. Как ваши сервисы справляются с ошибками (retry, circuit breaker, graceful degradation)?
Используются механизмы обработки исключений на уровне gRPC клиента и логирование ошибок. При сбоях шлюз возвращает понятные HTTP-статусы (500/503).

4. Как организован деплой и обновление вашей системы без простоя (Zero Downtime)?
В Kubernetes это реализуется через Rolling Update, когда новые поды запускаются параллельно со старыми до прохождения проверок готовности (Readiness probes).

5. Что было самым сложным в интеграции всех компонентов вместе?
Синхронизация схем данных между gRPC (Protobuf) и REST (JSON), а также настройка сетевой связности контейнеров в единой Docker-сети.

6. Что бы вы улучшили, если бы у вас был еще месяц?
Добавил бы полноценную базу данных (PostgreSQL), систему сбора метрик (Prometheus) и распределенную трассировку для отладки цепочек вызовов.
